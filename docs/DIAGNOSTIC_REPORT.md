# 本地诊断报告

在「更多 → 日志 → 运行诊断」或「关于 → 诊断」点击导出，Murge 会在本机生成相同的 JSON 文件，不自动上传。

报告包含一次应用启动的阶段耗时、当前内核/系统代理/TUN 状态、Windows 登录任务与核心服务状态、配置端口的监听 PID、系统代理注册表的启用状态与本机端口，以及最近两份应用日志中的错误**类别和次数**。启动耗时从 Electron 主模块初始化开始计算，不能直接等同于 Windows 开机耗时或外网恢复耗时。端口 PID 是采集瞬间的快照；端口若被其他程序重新占用，应重新导出报告。

报告不包含配置 YAML、订阅 URL、控制器密钥、原始日志、目标域名/IP 或网络请求。某项检查因权限或系统组件不可用而失败时，报告会标记为 `unavailable`，并在 `collectionWarnings` 中标出未采集项目，不会把未知状态写成正常。该操作只读，不启动/停止内核，也不修改系统代理或 TUN。

冷启动排查时，应同时查看 `startup.marks`、`runtime` 和 `host`：`kernel-ready` 只证明控制器已验证；`system-proxy-enabled` 与 `tun-active` 分别证明相应模式已完成启用；这些时间点本身不证明外网一定可达。应用当前只记录首次启动阶段，之后手动切换模式不会被误计入冷启动耗时。
